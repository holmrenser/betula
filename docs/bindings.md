# Language bindings

Each binding has one type per schema, named after the schema's title (see [Schemas](schemas.md)),
and a parse function that rejects exactly what the schema rejects. All three are tested against
every example document on the schema pages.

The usage code on this page is each binding's `examples/usage.*` file, included verbatim. CI runs
those files and checks their assertions, and fails if a public function or type isn't used in
them, so this page covers the whole hand-written API.

## Python

Pydantic v2 models generated by datamodel-code-generator. `parse` and `parse_json` validate in
Pydantic's strict mode, which is what makes them agree with the schema: calling
`Model.model_validate` directly would coerce, e.g., `"1"` into an int.

```bash
pip install "git+https://github.com/holmrenser/betula@v0.5.0#subdirectory=bindings/python"
```

```{literalinclude} ../bindings/python/examples/usage.py
:language: python
```

API reference: the docstrings on `parse` and `parse_json` (`help(betula.parse)`) carry examples
that run as doctests.

## TypeScript

Types generated by json-schema-to-typescript, validated at runtime by ajv against the same schemas.
`parse(kind, data)` is typed by the kind name, so `parse("Tree", data)` returns a `Tree`.

The package isn't on npm yet; build it from a checkout and install it from there:

```bash
git clone https://github.com/holmrenser/betula
cd betula/bindings/typescript && npm ci && npm run build
cd /your/project && npm install /path/to/betula/bindings/typescript
```

```{literalinclude} ../bindings/typescript/examples/usage.ts
:language: typescript
```

API reference: signatures and TSDoc comments ship in the package's `.d.ts` files, so they show up
in your editor.

## Rust

Serde types generated by typify. typify doesn't enforce every JSON Schema keyword, so `parse` and
`parse_str` validate against the schema with the `jsonschema` crate before deserializing.
Serializing and re-parsing gives an equal value, though empty optional arrays are omitted on
output.

```toml
# Cargo.toml
[dependencies]
betula = { git = "https://github.com/holmrenser/betula", tag = "v0.5.0" }
```

```{literalinclude} ../bindings/rust/examples/usage.rs
:language: rust
```

API reference: `cargo doc --open -p betula`; the doc comments' examples run as doctests.

## R

There's no JSON-Schema-to-R code generator comparable to the ones above. From R, read with
`jsonlite` and validate with the `jsonvalidate` package against the self-contained bundle from
`python3 scripts/bundle_schema.py` (the individual schema files `$ref` each other by URIs that
don't resolve over the network).
